● Medium API로 글을 작성하기 위해 필요한 정보를 정리했습니다.

  현재 Medium API 상태

  ⚠️ 중요: Medium은 공식 API를 더 이상 지원하지 않지만(2023년 3월 2일 아카이빙), 기능은 여전히 작동 중입니다. 다만 설정 메뉴에 숨겨져 있고, 2025년 12월 9일에 기존 classic tokens이 폐기될 예정입니다.

  ---
  당신이 준비해야 할 정보

  1. 인증 (Authentication)

  - Integration Token (통합 토큰)
    - Medium 계정 설정 → 통합 토큰 섹션에서 발급
    - 데스크톱 통합이나 플러그인용으로 설계됨
    - API 요청 시 Bearer 토큰으로 사용

  2. 글 작성에 필수적인 정보

  | 항목          | 설명        | 형식                   |
  |---------------|-------------|------------------------|
  | title         | 글 제목     | 문자열                 |
  | contentFormat | 콘텐츠 형식 | "html" 또는 "markdown" |
  | content       | 글 본문     | HTML 또는 Markdown     |

  3. 선택사항

  | 항목          | 설명      | 예시                          |
  |---------------|-----------|-------------------------------|
  | tags          | 태그      | ["AI", "프로그래밍"]          |
  | publishStatus | 발행 상태 | "public", "draft", "unlisted" |
  | canonicalUrl  | 원본 URL  | 다른 곳에 발행된 글의 URL     |

  4. Publication으로 발행할 경우

  - Publication ID 필요
  - 권한 레벨 확인:
    - Editor: 모든 상태(public, draft, unlisted)로 발행 가능
    - Writer: draft로만 발행 가능

  ---
  기본 API 엔드포인트

  POST /v1/me/posts
  인증된 사용자의 글을 작성합니다.

  ---
  다음 단계

  1. Medium 계정에서 Integration Token 발급
  2. User ID 확인 (Token으로 GET /v1/me 요청)
  3. 글 데이터 준비 (title, content, contentFormat 등)
  4. API 요청 실행

● ⚠️ 중요한 소식

  Medium은 2025년 1월 1일부터 새로운 Integration Token 발급을 중단했습니다.

  ---
  기존 토큰이 있는 경우 (계속 작동함)

  이전에 발급받은 토큰이 있다면:
  1. Medium 계정에 로그인
  2. 우측 상단 프로필 사진 클릭
  3. Settings 선택
  4. 좌측 메뉴에서 Integration tokens 선택
  5. 기존 토큰이 표시됩니다 (계속 사용 가능)

  ---
  새로운 토큰이 필요한 경우

  문제: Medium이 API를 신규 통합에 대해 폐쇄했습니다.

  대안 솔루션

  1. 기존 토큰 확인: 혹시 이전에 Medium API를 사용했던 토큰이 있는지 확인
  2. OAuth 인증 확인: Medium이 다른 인증 방식을 제공하는지 확인
  3. 비공식 API 사용: https://mediumapi.com/ 같은 비공식 서비스 검토

  ---
  요약

  - 기존 토큰: 계속 작동하므로 Settings → Integration tokens에서 확인
  - 새 토큰: 2025년 1월 이후 발급 불가능
  - 전망: Medium의 API 정책 변화로 인해 공식 지원이 제한적

  혹시 이전에 발급받은 토큰이 있으신가요?

  1. 비공식 API 사용 (추천)

  3. Medium 공식에 문의

  - Medium 지원팀에 API 액세스 요청
  - 특수한 경우(예: 출판사, 대량 콘텐츠 관리) 예외 가능성

  현실적인 대안

  1️⃣ 웹 자동화 (가장 빠른 테스트)

  - Puppeteer (Node.js) 또는 Selenium으로 직접 Medium 웹사이트 조작
  - 장점: 지금 바로 테스트 가능
  - 단점: 불안정, Medium 약관 위반 가능성

  2️⃣ 자동화 플랫폼 (가장 안정적)

  - n8n, Make, Zapier 등에서 Medium 통합 제공
  - 기존 token 있는 경우만 가능

  3️⃣ 다른 블로깅 플랫폼 (추천)

  - Dev.to - 공식 API로 글 작성 가능 ✅
  - Hashnode - 공식 API로 글 작성 가능 ✅
  - Medium 대신 이들을 사용하면 지금 바로 테스트 가능

  ---
  당신의 선택?

  - Medium에 꼭 써야 하나요? → 아니면 Dev.to/Hashnode로 테스트하시는 게 훨씬 간단합니다
  - Medium 고집 → Puppeteer 웹 자동화로 테스트하거나, 누군가에게 기존 token을 받아야 합니다

  핵심 설계 원칙

  1️⃣ Publisher 인터페이스 (공통 구조)

  abstract class Publisher {
    abstract login()
    abstract publish(post: Post)
    abstract logout()
  }

  2️⃣ 플랫폼별 구현

  - 각 플랫폼의 login(), publish(), logout() 구현
  - Playwright 셀렉터/로직은 플랫폼별로 다름

  3️⃣ 글 데이터 정규화

  interface Post {
    title: string
    content: string      // HTML로 통일
    tags?: string[]
    category?: string
    isPublic?: boolean
    platformConfig?: {   // 플랫폼별 옵션
      medium?: { ... }
      tistory?: { ... }
      naver?: { ... }
      branch?: { ... }
    }
  }

  ---
  처리 흐름

  1. 글 준비 → Post 객체 생성
  2. Publisher 선택 (Medium, Tistory, 네이버, 브런치)
  3. 각 Publisher가:
     - 로그인
     - 글 데이터를 플랫폼에 맞게 변환
     - Playwright로 UI 자동화
     - 발행
     - 로그아웃
  4. 결과 기록 (성공/실패)
